# 设计文档：日文 EPUB 翻译工坊

> 状态：v0.1（框架定稿，待评审）
> 目标读者：本项目开发者（含未来的我）
> 一句话：这不是"翻译器"，而是一条**译文生产线 + 一套质量控制台**。

---

## 1. 项目定位

### 1.1 问题

- 新出的日文推理小说没有中译本，日语水平不足以直接读；
- 直接把整章丢给 LLM，产出"每个句子都对、整本书是垃圾"的译文；
- 译文难以回到 EPUB，格式（注音、脚注、插图、目次）全毁。

### 1.2 四个失败根源

| 层次 | 故障 | 根因 |
|---|---|---|
| 语篇 | 主语乱补、代词指错、对话归属错乱 | 翻译时看不到上下文 |
| 术语 | 人名/警衔/科学术语前后不一 | 没有跨章记忆 |
| 文体 | 敬语层级抹平、一人称口吻丢失、方言变普通话 | 没有人物与风格画像 |
| 结构 | 注音、傍点、脚注、插图、目次被破坏 | 粗暴切块 + 重建 DOM |

再加上工程层的三个隐形杀手：中断要全量重跑、成本不可控、改一次 prompt 无法回归验证。

### 1.3 目标函数

**保真优先，可读其次，绝不添油加醋。**

推理小说里"译者自作聪明补一句解释"可能直接毁掉整本书的谜底。因此宁可略微生硬，也不允许增译；宁可加译注，也不允许把日文双关"本地化"掉。

### 1.4 非目标（v1 明确不做）

- 不做实时/整页网页翻译（那是沉浸式翻译的赛道）；
- 不做 PDF 直接翻译（先做 EPUB，OCR 链路只预留接口）；
- 不做 DRM 破解；
- 不做多语言互译，v1 只做 ja → zh-Hans（架构上留 lang pair 参数）。

## 2. 质量模型

### 2.1 错误分类法（QA 与评测共用）

| 代码 | 类型 | 判定 | 严重度 |
|---|---|---|---|
| E-OMIT | 漏译 | 原文有信息，译文缺失 | 高 |
| E-ADD | 增译/杜撰 | 译文出现原文没有的信息（尤其情节、线索、动机） | **致命** |
| E-MIS | 误译 | 意思错 | 高 |
| E-TERM | 术语不一致 | 同一实体多种译法，或违背术语表 | 中 |
| E-REG | 语体偏移 | 敬语层级、人称口吻、方言感丢失或错位 | 中 |
| E-AMB | 歧义破坏 | 原文故意模糊处被说死（含性别、时间、身份） | **致命**（诡计类） |
| E-FMT | 格式破坏 | 标记、注音、脚注、引号配对出错 | 高 |
| E-FLU | 不流畅 | 中文不可读、翻译腔、主语堆砌 | 低 |

"致命"级别一票否决：不论其他维度多好，该批次不得进入发布。

### 2.2 质量目标（可度量）

- 硬校验通过率：100%（不允许任何标记/术语/数字错误进产物）；
- 术语一致率：≥ 99.5%（黄金集）；
- 红旗段落人工改动率：≤ 15 字/千字；
- 通读抽检（每章 2 段）：致命错误 0，E-MIS ≤ 1/万字。

## 3. 总体架构

### 3.1 分层

```
┌─────────────────────────────────────────────────────────┐
│ L7 人机界面  预读确认 / 试译校准 / 双语审校 / 术语快加 / 导出 │
├─────────────────────────────────────────────────────────┤
│ L6 输出      EPUB3 重建 · CSS · 注音策略 · 元数据 · 校验    │
├─────────────────────────────────────────────────────────┤
│ L5 质量门    硬校验（确定性） + 软校验（LLM rubric）        │
├─────────────────────────────────────────────────────────┤
│ L4 翻译引擎  预读 → 草稿 → 自评 → 修订 → 润色 → 校验        │
├─────────────────────────────────────────────────────────┤
│ L3 知识层    术语库 · 人物圣经 · 风格指南 · 系列记忆 · 风险   │
├─────────────────────────────────────────────────────────┤
│ L2 结构分析  章节 / 场景 / 对话 vs 叙述 / 标题 / 脚注 / 注音  │
├─────────────────────────────────────────────────────────┤
│ L1 IR       段/句单元 + 内联标记骨架 + 原文串区间            │
├─────────────────────────────────────────────────────────┤
│ L0 接入     EPUB 校验 · DRM 检测 · OPF/spine 解析 · 体检报告 │
└─────────────────────────────────────────────────────────┘
```

### 3.2 数据流

```
source.epub
  → [ingest]  → report.json（结构体检）
  → [ir]      → units.jsonl + markup.json（原文串 + 区间）
  → [analyze] → book_bible.yaml（人物/术语/风险/风格初稿）
  → 【人工确认点 1】
  → [translate] → units.jsonl（多版本译文）+ 缓存
  → [qa]      → qa_report.json（红旗列表）
  → 【人工审校点 2】
  → [build]   → out.epub → epubcheck → 试读
```

### 3.3 核心原则

1. **单向数据流**：每层只读上一层产物、只写自己的产物，任何一步可独立重跑。
2. **内容寻址**：缓存以 `hash(原文 + 术语表版本 + prompt版本 + 模型 + 参数)` 为键，保证幂等与可复现。
3. **人工只看红旗**：人类的注意力是稀缺资源，只投向风险 × 影响最高的段落。
4. **可降级**：模型调用失败、预算耗尽、JSON 解析失败时，能退回上一版草案并继续，不阻塞整本书。

## 4. 模块规格

### 4.1 L0 接入（ingest）

职责：

- 校验 zip 结构：`mimetype` 必须是第一个 entry 且 stored（不压缩）、`META-INF/container.xml` 存在；
- 解析 `container.xml → OPF → manifest / spine / spine 顺序 / nav / NCX`；
- **DRM 检测（分级，不能一见 `encryption.xml` 就拒）**：
  - `META-INF/license.lcpl` 存在 → Readium LCP，**判定 DRM，拒绝**；
  - `encryption.xml` 中含 LCP/ADEPT 的 `RetrievalMethod` → **判定 DRM，拒绝**；
  - `encryption.xml` 只含 IDPF/Adobe **字体混淆**条目 → 不是 DRM（规范原文 "obfuscation is not encryption"），**可处理**，仅标记"字体已混淆，需解码后重新打包"；
  - Kindle/Kobo 商店书是 AZW/KFX 私有容器，不进入本流水线；
- 编码与语言：检测 `xml:lang`、`dc:language`，非 `ja` 时警告；
- 清点：章节数、图片数、脚注数、ruby 数、`epub:type` 分布、CSS 书写模式（是否 `vertical-rl`）；
- 生成 `report.json`，这是"体检报告"，也是后续所有决策的输入。

输出：`report.json`、`spine.json`（章节顺序与文件路径）。

### 4.2 L1 中间表示（IR）——整个项目的地基

**原则：原文串不可变，译文只做区间替换。**

#### 4.2.1 单元（Unit）

翻译的最小单位是**段（paragraph）**，句（sentence）是段内子单元。理由：日语段落常由多个短句构成，中文往往需要合并，"以段为单位、允许内部重组"比"以句为单位、禁止越界"更贴近实际译法。

```jsonc
{
  "id": "ch02-p017",
  "chapter_id": "ch02",
  "order": 17,
  "kind": "narration",            // narration | dialogue | heading | note | caption | title
  "source": "彼は黙って窓の外を見ていた。⟦0⟧そう言えば、あの日も雨だった。⟦1⟧",
  "spans": [                       // 占位符 ↔ 内联标签
    {"marker": "⟦0⟧", "tag": "ruby", "base": "雨", "rt": "あめ", "class": "ruby-reading"},
    {"marker": "⟦1⟧", "tag": "span", "class": "emphasis-dots"}
  ],
  "raw_range": [10240, 10512],     // 在原文 XHTML 字符串中的字符区间
  "prev": "ch02-p016",
  "next": "ch02-p018",
  "risk": {"score": 0.2, "tags": []},
  "state": "pending"               // pending | drafted | revised | verified | approved
}
```

#### 4.2.2 回写策略（最关键的一条决策）

**不做 DOM 重新序列化。** 做法：

1. 读入 XHTML 原始字符串 `raw`，原样保存；
2. 用解析器（lxml）建树，但只为**定位**：给每个文本节点记录其在 `raw` 中的 `[start, end)` 区间；
3. 翻译只产生"该段的新文本"；
4. 回写时对 `raw` 做**从后往前的区间替换**（避免偏移失效），生成新 XHTML。

这样属性顺序、实体转义、命名空间、注释、空白全部零改动。验收标准：**未翻译的文本节点之外，输出与输入逐字节相同**。

#### 4.2.3 内联标记策略

| 标签 | 策略 |
|---|---|
| `<ruby>` 振假名（读音） | 中文输出中删除注释，只保留被注词的译法 |
| `<ruby>` 当て字/義訓（表意） | 保留原词 + 括注，或转为译注（见 4.2.5） |
| `<ruby>` 被标为诡计相关（Q12/Q31） | **一律保留**，优先级高于"读音/语义"二分；先查 risk.yaml 再判类型 |
| `<rp>` 回退括号 | 随 ruby 一起处理；删 ruby 时连 `rp` 一并删 |
| complex ruby / 左右 ruby | **不支持，不建模**：直接降级为"原词（读作 X）"括注 |
| `<em>/<b>/<i>` | 保留，位置按占位符 |
| `<a>` 脚注锚点 | 保留 href 与 id，脚注正文单独翻译 |
| `<img>` | 保留；`alt` 与 `figcaption` 翻译 |
| `<span class="tcy">` | 删除包装，保留文本 |
| `<br>` | 保留 |
| 注释 `<!-- -->` | 原样保留 |

#### 4.2.4 重新分段的对齐问题

日语长句译成中文常需**拆分或合并**，单元边界不再是 1:1。处理：

- 翻译请求以**块（block，默认 = 一章内的连续段落）**为单位，返回块内文本；
- 占位符必须**数量与顺序守恒**，位置可移动；
- 若占位符丢失/重复 → 该块降级为逐段重译，仍失败则标记人工；
- 回写时按"段 → 新文本"映射；若一段被拆成多段，则按占位符位置切分并复制外层段落属性（首行缩进等）——这是唯一允许改变段落数的场景，且要记录在 `rewrite_log.json`。

#### 4.2.5 注音（ruby）判定

```
if 注音是 base 的假名读法（去掉送假名后比对，或查读音词典/模型判断为"读音"）:
    → reading：中文不需要，删除
else:
    → semantic：可能是当て字、義訓、双关、人名特殊读法
    → 保留 base 原词，首次出现加括注「（原文：X，读作 Y）」
    → 若 base 本身是诡计关键（如名字读法决定凶手），升级为 E-AMB 红旗
```

判定结果写入术语库，全书复用。

**范围约束**：只处理 HTML 简单 ruby（`ruby/rb/rt/rp`）。complex ruby（左右 ruby、多列 ruby）浏览器支持差，青空文庫自身也曾因此退回 simple-ruby，本项目遇到即降级为括注，不建模、不尝试还原。

### 4.3 L2 结构分析（analyze）

- 章节切分：按 spine + `<h1>-<h3>` + 分页符；短篇集按作品标题切；
- 场景分隔：`＊`、`◇`、空行、`<hr>`、居中装饰 —— 识别并保留，不吞掉；
- 对话 vs 叙述：以 `「」『』` 包裹判定，`kind=dialogue`；
- 说话人归属：对话段落的 speaker 由模型结合作品上下文推断，写入 `speaker` 字段（不确定则留空 + 低置信标记，供审校确认）；
- 脚注/译注：`epub:type="noteref"` 与 `footnote` 成对处理；**v1 原书脚注标 opaque，原样保留日文、不翻译**（Q12/O5），新增译注走独立编号，不与之混排；
- 标题与目次：`nav.xhtml` / NCX 的 label 单独翻译，与正文标题**必须一致**（硬校验项）。

### 4.4 L3 知识层

四个文件，全部 YAML/Markdown，可被人直接编辑，也可是模型的输出：

#### 4.4.1 `book_bible.yaml`

```yaml
book:
  title_ja: 例の書名
  title_zh: 中文书名
  author_ja: 作者名
  series: {name: 系列名, index: 3}
  genre: mystery
  pov: first_person          # first_person | third_limited | omniscient | epistolary
  narrative_tricks: [gender_concealment, unreliable_narrator]
  tone: 硬汉派/本格/社会派/日常之谜
  era: 平成初期
characters:
  - id: c01
    name_ja: 御手洗潔
    reading: みたらい きよし
    name_zh: 御手洗洁
    gender: male              # male | female | hidden ← hidden 表示原文有意不揭示
    age: 30s
    role: 侦探
    register: 丁寧・論理調・やや芝居がかった
    pronouns: {first: 私, address_to_others: 君/さん}
    relationships: [{to: c02, type: 旧知, register: タメ口}]
    first_appearance: ch01
```

`gender: hidden` 是**硬约束**：翻译该角色相关段落时禁用"她/他"指代，改用名字或重构。

#### 4.4.2 `glossary.yaml`

```yaml
- ja: 警部補
  zh: 警部补
  level: exact             # exact（唯一译法，禁用其他） | preferred（优先） | free
  inflectable: false       # 是否允许按中文语流变化（人名/术语一般 false）
  category: 警务
  note: 日本警衔，位于警部之下、巡査部長之上
  first_seen: ch01-p003
  forbidden: [警部助理, 副警部]
- ja: 死後硬直
  zh: 尸僵
  level: must
  category: 法医
```

检索策略：按当前块中出现的术语做**子串/词形匹配**，只注入命中的条目（避免 prompt 膨胀）。

#### 4.4.3 `style_guide.md`

人类可读的规则 + 少样本：

- 语体：简体中文，叙述用过去时态感，对话口语化程度中等；
- 敬语映射表：`です・ます` → 中性礼貌；`でございます` → 书面敬语；`〜ていただく` → "承蒙…"；
- 人称：一人称叙述尽量省略主语；确需时用"我"；
- 数字：阿拉伯数字；年份用"昭和X年（XXXX年）"首次括注；
- 标点：`「」→""`，`『』→''`，`、→，`，`……` 保留，`！？` 归一；
- 译注格式：脚注，前缀"译注："；
- 禁用词表：翻译腔（"进行…的动作"、"对于…来说"滥用）、日式汉语（"大丈夫"、"一生悬命"）。

#### 4.4.4 `risk.yaml`

```yaml
- unit: ch07-p042
  tags: [gender_concealment, trick_clue]
  policy: avoid_pronoun, do_not_explain
  note: 此处叙述者刻意模糊性别，禁止补主语
```

风险标签枚举：`gender_conceal`, `wordplay`, `name_reading`, `dialect`, `keigo_shift`, `unreliable_narrator`, `trick_clue`, `timeline_trick`, `foreigner_speech`, `legal_terms`。

### 4.5 L4 翻译引擎

#### 4.5.1 六个阶段

| 阶段 | 输入 | 输出 | 模型档位 |
|---|---|---|---|
| P0 预读 | 全书（分块 map-reduce） | book_bible 初稿 + 章节摘要 + 风险候选 | 强 |
| P1 草稿 | 单元 + 三层上下文 + 术语切片 | 直译优先的初稿 | 中/便宜 |
| P2 自评 | 原文 + 初稿 + checklist | MQM 式 span 级问题清单（片段 + 类型 + 严重度） | 强（仅红旗/抽样） |
| P3 修订 | 原文 + 初稿 + 问题清单 | 修订稿 | 强 |
| P4 润色 | 修订稿 + 风格指南 | 中文可读性稿（**禁止改情节**） | 中 |
| P5 校验 | 原文 + 终稿 | 通过 / 退回 | 便宜 + 规则 |

P1 必须**直译优先**：先保证信息不丢，再谈文采。P2/P3 只对 `risk.score > 阈值` 的单元执行，控制成本。P4 的红线是"只改表达，不改事实"，靠提示词 + 译后数字/人名/术语硬校验兜底。

#### 4.5.2 上下文组装（三层记忆）

```
[System]  角色 + 保真铁律 + 输出 JSON 格式
[Book]    书名/作者/类型/POV/叙述诡计清单/整体语调
[Style]   风格指南（压缩版，~500 token）
[Chars]   本章出场人物卡（只取相关）
[Gloss]   本块命中术语（must 级全量，should 级抽样）
[Summary] 前情摘要（滚动，~300 token）+ 本章已译部分摘要
[Window]  前 2 段原文 + 后 2 段原文（前瞻，解决零主语的关键）
[Task]    待译块（带 id）
```

前瞻窗口是解决日语零主语的**最有效手段**：答案往往在下一句。

#### 4.5.3 结构化输出

强制 JSON：

```json
{"units": [{"id": "ch02-p017", "text": "……"}, ...]}
```

校验：id 集合必须与请求完全一致；缺失 → 重试（最多 2 次）→ 仍失败则退回单段翻译。**这是防止模型"顺手省略一段"的唯一可靠办法。**

#### 4.5.4 路由与成本

- 难度打分（规则 + 轻量分类器）：对话密度、敬语密度、平均句长、术语密度、风险标签；
- 低难度：P1 + P5；
- 中：P1 + P3 + P5；
- 高：P1 + P2 + P3 + P4 + P5，必要时双模型交叉 + 仲裁。

- **推理层解耦**：所有模型调用走同一套 OpenAI 兼容接口，`providers.local`（租用 5090 上的 vLLM/Ollama，按需开机）与 `providers.cloud` 可互换；开机前健康探测，失败自动降级云端并提示；成本双计量（GPU·小时 / token·人民币）；
- **预算控制**：按书设上限（token / 金额），超限暂停并提示，绝不静默烧钱。

### 4.6 L5 质量门

#### 4.6.1 硬校验（确定性，全部必须通过）

1. **占位符守恒**：数量、顺序、类型一致；
2. **未译残留**：译文中的平假名/片假名比例超阈值即报警；常见日文汉字词（"〜ている"、"という"）词表扫描；
3. **术语合规**：`must` 级术语的 `forbidden` 译法零出现；
4. **数字一致**：抽取原文与译文中的数字/日期/时刻/金额集合，要求包含关系成立（允许中文数字写法归一）；
5. **人名一致**：同一 `name_ja` 全书只对应一个 `name_zh`；
6. **长度比**：`len(zh)/len(ja)` 落在 [0.45, 1.1]，越界人工看（通常意味着漏译或增译）；
7. **标点配对**：`""`、`''`、`（）`、`《》` 配对；引号嵌套层级正确；
8. **段落数与空段**：与预期一致（允许 4.2.4 记录的合法拆分）；
9. **目次一致**：nav/NCX 的 label 与正文标题逐字相同。

#### 4.6.2 软校验（LLM rubric，只对红旗 + 抽样）

五维 1–5 分：保真、流畅、语体匹配、歧义保留、无新增信息。
任何维度 ≤ 2 或"无新增信息" ≤ 3 → 退回修订。

### 4.7 L6 输出

- **结构**：复用原 OPF/spine，替换文本；新增的只有 `dc:title`（中文）、`dc:language`（zh-Hans）、`dc:identifier`（新 UUID）、`dc:source`（原书标识）、`dc:contributor`（"AI 辅助翻译，人工审校"）；
- **目次**：nav.xhtml 与 NCX 同步重建，标题用译文；
- **CSS**：**不改原 CSS**，另加一个 `translator.css` 覆盖必要项（首行缩进、引号字体、注音隐藏）；原 `vertical-rl` 在中文版转为 `horizontal-lr`（简中读者习惯），通过覆盖 `writing-mode` / `-epub-writing-mode` 实现，不改原文件；**同时必须把 OPF `spine@page-progression-direction` 改回 `ltr`**，否则翻页方向相反（只改 CSS 不改这个是常见翻车点）；
- **注音**：按 4.2.5 处理，`reading` 类直接删除 `<rt>`，`semantic` 类保留并加括注；
- **脚注**：保留原 popup 机制；新增译注插入同一 footnote 区，编号续接；
- **元数据**：保留原 `dc:title` 作为 `alternative`，加 `dcterms:modified`；
- **校验**：`epubcheck` 必须 0 error；再用 calibre / Apple Books 打开抽检 3 章。

### 4.8 L7 人机界面

v1 形态：本地 Web（FastAPI + 简单前端），因为审校是核心而非附属。

四个界面：

1. **体检页**：结构统计、风险提示（DRM、竖排、ruby 数量、异常章节）；
2. **预读确认页**：人物表 / 术语表 / 风险清单，可编辑、可勾选"确认后开始"；
3. **试译校准页**：原文 vs 2–3 个风格变体，用户选一个并修改，系统把修改蒸馏进 style_guide（规则 + few-shot）；
4. **审校页（因"用户不读日文"而重新设计）**：

```
左：中文译文（主视图，可编辑）
中：事实清单（系统从原文提取，用中文列出：谁 / 做了什么 / 时间 / 地点 / 关键线索）
右：术语卡 + 红旗理由（中文）｜ 原文默认折叠，仅备查
```

配套三条：

- **事实清单核对**：P0 预读即为每段生成中文"信息点"，译后逐条检查是否被覆盖——用户不需要读日文就能判断"有没有丢东西"；
- **直译 / 润色双版本对照**：同段给出字面直译版与润色版并高亮差异，**增译、漏译在两个中文版本之间就能看出来**，这是不懂日语者唯一可靠的 E-ADD/E-OMIT 抓手；
- **红旗只推中文侧可判断的类型**：术语不一致、翻译腔、长度比异常、代词密集、双版本差异过大；纯保真问题由系统判定，不推给人。

## 5. 日语 → 中文 语言工程规范

| 现象 | 风险 | 策略 |
|---|---|---|
| 零主语 | 补错主语 | 前瞻窗口 + 人物在场表；不确定时保留无主句 |
| 授受动词 | 恩惠方向错 | 显性化但保持亲疏（"承蒙…"/"替我…"） |
| 敬语层级 | 关系信息丢失 | 建立"敬语等级 → 中文表达"映射表；层级变化必须可见 |
| 人称性别 | **泄底** | `gender: hidden` 角色禁用性别代词 |
| 警衔/司法 | 读者看不懂权力关系 | 术语库统一 + 首现译注 |
| 方言 | 地域信息丢失 | 轻度口语化 or 标准语 + 译注；若为线索则保留原文 |
| 谐音/字谜/回文 | **谜底失效** | 保留原文 + 括注 + 译注，禁止本地化 |
| 名字读法 | 线索丢失 | 保留读音，首现括注 |
| 拟声拟态词 | 直译生硬 | 改写为动作/氛围描写 |
| 元号/单位 | 理解障碍 | 首现括注公历/公制 |
| 标点体系 | 引号嵌套错乱 | 状态机转换 + 配对校验 |
| 竖排 | 阅读体验 | 转横排，CSS 覆盖 |

## 9. 评测

- **黄金集**：青空文庫公有领域推理作品（乱歩、夢野久作、大阪圭吉等）原文 + 自译/授权译文；每篇 3000–5000 字，覆盖对话、叙述、方言、字谜各一类。
- **指标**：错误分类法计数（见 2.1）+ 五项 rubric 均分 + 人工改动率（编辑距离/千字）。
- **不用 BLEU 做主指标**；COMET/xCOMET 只在**同一本书、同一模型家族**内做版本回归（分数下降即报警），不跨书比较，也不作为发布结论。
- **错误分类与 MQM 对齐**：2.1 的 E-* 需显式映射到 MQM 的 accuracy / fluency / terminology / style 四支，文献与人评都以此为准（WMT24 即用 MQM）。
- **软校验优先用 span 级输出**：P2 自评要求模型给出"错误片段 + 类型 + 严重度"，而非只给分数，便于直接定位。
- **回归**：prompt/模型/术语表任何变更，自动重跑黄金集 + 一本真实书的固定 2 章，输出 diff 报告；指标下降则阻止合并。

## 10. 风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模型对文学语感的 ceiling | 译文"对但不好看" | P4 润色 + 用户风格校准；接受"好读的直译" |
| 长程一致性 | 后章与前章矛盾 | 滚动摘要 + 术语硬校验 + 全书一致性审计 |
| 情节幻觉 | **推理小说致命** | 禁止增译铁律 + 数字/人名校验 + 红旗人工 |
| 版权 | 法律风险 | 仅处理合法获得的副本；产物限个人使用，不提供分发功能 |
| 成本失控 | 钱包 | 预算上限 + 缓存 + 难度路由 |
| 评测主观 | 无法判断改进 | 黄金集 + 固定 rubric + 人工改动率 |

开放问题（需作者拍板）：

1. 中文语体：大众出版物 vs 轻小说口语化？影响 P4 与标点策略。
2. 译注密度：脚注越多越忠实但越打断阅读，默认阈值待定。
3. 是否需要"双语对照版 EPUB"输出（原文/译文交替），对学习有价值但排版复杂。
4. 是否引入本地模型做 P1 草稿以降本。

## 12. 决策记录（ADR）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | 原文串区间替换，不重建 DOM | 格式零破坏 | 需要精确区间映射 |
| D2 | 以段为翻译单位，允许块内重组 | 贴近真实译法 | 对齐逻辑复杂 |
| D3 | 强制 JSON 结构化输出 | 防漏段、可校验 | 模型需支持 JSON |
| D4 | 术语用机制保证而非提示词 | 可靠性 | 需维护术语库 |
| D5 | 风险分级路由 | 成本与质量平衡 | 需难度打分器 |
| D6 | 人工只审红旗 | 效率 | 依赖红旗召回率 |
| D7 | 默认横排简中 | 读者习惯 | 竖排爱好者不满（可配置） |
| D8 | 内容哈希缓存 | 幂等、可复现、省钱 | 缓存键需覆盖全部变量 |
| D9 | 输入解耦，OCR 只留接口 | 聚焦 | PDF 用户暂时无法用 |
| D10 | 只支持 simple ruby，complex ruby 降级括注 | 阅读器支持差，还原成本高于收益 | 少数书注音信息丢失 |
| D11 | COMET 只做同书回归，不进发布门 | 文学维度与专业判断相关性差 | 需要人工抽检兜底 |
| D12 | 绝不把"回填 XML"交给 LLM | 一个标签错就毁格式 | 回写层必须自研 |
| D13 | 本地 Web + 远端按需 GPU，状态留本机 | GPU 是临时资源，状态不能跟着丢 | 需健康探测与降级 |
| D14 | 原书脚注 v1 不翻译，原样保留 | 降低复杂度，且用户不读日文 | 书里会混入日文脚注 |
| D15 | **默认丢弃注音（ruby）与排版 span** | 中文读者无法使用假名；且它们是标记丢失与重试风暴的根源 | 丢失原书读音；诡计相关靠译注兜底 |
