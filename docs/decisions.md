## 3. 两个需要重新设计的地方

### 3.1 "用户不懂日语"推翻了审校界面的前提

原设计（design.md 4.8）假设用户能对照日文判断。**实际不能**。三栏改成：

```
左：中文译文（主视图）
中：事实清单（系统从原文提取，用中文列出：谁 / 做了什么 / 时间 / 地点 / 关键线索）
右：术语卡 + 红旗理由（中文）+ 可折叠的原文（仅备查）
```

配套机制：

1. **事实清单核对（Fact Checklist）**：P0 预读阶段就为每段生成"信息点"（中文），译后检查每个信息点是否在译文中被覆盖。用户只需看"这些点都写到了吗"，不需要读日文。
2. **直译/润色双版本对照**：同一段给"字面直译版"和"润色版"，差异高亮。**增译、漏译在中文之间就能看出来**——这是不懂日语的用户唯一能有效抓 E-ADD/E-OMIT 的手段。
3. **红旗只放"中文侧可判断"的类型**：术语不一致、句式翻译腔、长度比异常、代词密集、双版本差异过大。纯保真问题由系统判定，不推给人。
4. 原文默认折叠，避免用户产生"我看不懂所以跳过"的挫败感。

### 3.2 脚注不处理，会影响结构

v1 策略：原书脚注**原样保留日文**，`epub:type="noteref"/"footnote"` 链接不动。后果：

- 中文正文里会突然出现一段日文脚注——可接受（用户自用），但要在体检报告里提示；
- 新增译注（Q30 的字谜解释）走**独立编号**，与原有脚注分开，避免冲突；
- 因此 IR 必须把 footnote 标为 `opaque`，不进入翻译队列。

## 4. 关于 Q05：第一本该选"有译本的经典"吗？

**建议两条线分开，不要用一本书同时满足两个目的。**

**评测线：可以用有参照的文本，但有陷阱。**
经典日本推理（《占星术杀人魔法》《嫌疑人X的献身》《白夜行》这类）的中译本在网上极多，**大概率已在模型训练数据里**。用它评测等于让模型"背答案"，分数会虚高，而且无法反映真实新书的难度。所以：

- 参照文本优先选**公版旧译**（青空文庫作品 + 早期译本），只用于核对**忠实度与术语**，不用于评风格（旧译文风过时）；
- 若要评风格，用你自己手译的 3000 字（Q39 你选了 B，但建议至少补 1000 字自译，作为风格锚点）；
- 更强的做法：选 **2024 年之后出版**的新书做验收，基本可排除训练数据污染。

**实战线：第一本选你真正想读的，但要满足三个条件。**
非系列第一本 · 结构常规（横排、ruby 少、脚注少）· 8–12 万字。先翻第一章给你读——"读不读得下去"比任何指标都准。

**折中方案（推荐）**：开发期用一本**有中译本的老书**跑通管线（不追求质量，只验证工程），验收期换**你想读的新书**。这样既不会被"背答案"骗，也不会拿新书当小白鼠。

## 7. 形态定案：本地 Web + 远端按需 GPU

### 7.1 拓扑

```
[Windows 本机]                         [租用 5090 / 32GB]
 浏览器 UI ── FastAPI ── SQLite    ──HTTP(OpenAI 兼容)──▶ vLLM / Ollama
 文件产物 · 缓存 · 术语库                    ▲
                                            │ 关机/失败时降级
                                       [云 API]（修订 / 红旗段落）
```

理由：

1. **状态必须在本机**。租的机器是临时的，进度、术语库、缓存、译文版本一旦放在远端，开机/关机就会丢或要反复同步；
2. **审校不需要 GPU**。GPU 只在"跑批"时开，其余时间照样能审校、改术语、导出；
3. **换供应商只改 endpoint**。本地/云走同一套 OpenAI 兼容接口，配置里切一行；
4. **桌面 App 只是外壳**。等流程稳定后用 Tauri 包一层即可，不返工。

### 7.2 对实现的硬约束

| 约束 | 原因 |
|---|---|
| 任务分块 ≤ 20–30 分钟一批 | GPU 按小时租，断电/回收是常态 |
| 每块完成即落盘 + 幂等缓存 | 重跑不重复烧钱 |
| 启动前探测 endpoint 健康，失败自动降级云端并提示 | 不能卡死 |
| 成本双计量：`GPU·小时` 与 `token·人民币` | 两种成本结构完全不同 |
| 本地模型只跑 P1 草稿（必要时 P4 润色），P2/P3 用云 | 32B 做文学修订不够稳 |
| 模型清单与量化格式写进配置，不写死代码 | 换机器/换模型不改代码 |

### 7.3 模型档位建议（5090 32GB 实测前为预估）

| 用途 | 建议 | 说明 |
|---|---|---|
| P1 草稿 | 30B 级 MoE（激活 ~3B）或 32B AWQ | 吞吐优先，~40–60 tok/s 可接受 |
| P4 润色 | 同本地模型或云端中档 | 只改表达，风险低 |
| P2 自评 / P3 修订 | 云端强模型 | 决定质量上限，不能省 |
| 兜底仲裁 | 云端强模型 | 仅红旗段落 |
