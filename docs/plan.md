# 方案总览

> 2026-11-19。代码已开源（MIT）。这份文档回答：系统现在是什么、还差什么、接下来怎么走。

## 1. 定位与边界

**做什么**：把日文小说 EPUB 变成中文 EPUB，输出可直接阅读、结构不坏、术语统一的成品。

**不做什么**：

- 不处理 DRM（LCP/ADEPT/Kindle）；
- 不做网页/PDF 输入（暂无需求）；
- 不做多语言对（架构留了口，未实现）；
- 不追求"出版级"文采，目标是"读得下去、不出错"。

## 2. 系统架构

四层，每层只依赖上一层产物：

```
① 拆装层    scan → IR → render → package
            原文串区间替换，除文本外逐字节不变

② 知识层    preread → glossary / style / 风险 → NameResolver
            全书一份权威，正文/标题/目录/注记共用

③ 翻译层    P0 预读 → P1 草稿 → P2 自评 → P3 修订 → P4 润色
            批处理 + 三层记忆 + 并发 + 内容哈希缓存

④ 质检层    结构 / 术语 / 标点 / 假名 / 一致性 / 数字
            硬校验自动修，判断题留给人
```

配套：审校界面（问题清单 → 段落 → 改 → 重打包）、断点续跑、原子落盘。

## 3. 质量模型

| 类型 | 例子 | 处理 |
|---|---|---|
| 硬错误 | 术语不一致、标记丢失、引号不配对 | 自动检测 + 自动修 |
| 半硬 | 整段未译、假名残留 | 自动重译，失败保留原文并标记 |
| 软问题 | 翻译腔、语气不准 | 润色 + 人工判断 |
| 致命 | 泄底、增译、把含糊说死 | 提示词硬约束 + 风险段落标注 |

## 5. 已验证失败的设计

1. **风险分级路由**——表层特征预测不了错误（覆盖 6% 只抓 15%）；
2. **三层记忆**——单段收益极小（50→46），价值在跨章一致性；
3. **别名自动定名**——模型会重新发明译名，必须人工确认。

## 7. 路线

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 模型换了导致质量波动 | 译文变差 | 黄金集回归 |
| 版权争议 | 仓库被投诉 | 仓库不含书、不含译文；README 声明 |
| 字体授权 | 分发违规 | 换开源字体 |
| 长书一致性 | 后段人名漂移 | 术语表 + 一致性检查（已有效） |
